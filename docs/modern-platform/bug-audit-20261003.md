# Source bug audit — 2026-10-03

This batch reviews the modern engine from C++ sources and existing contracts,
starting at `5b17cc1a`. It does not inspect other attempted engine projects or
change authored Mod content. The audit is focused, not a claim that all engine
bugs have been eliminated.

## CV2 allocation bounds

The raw CV2 loader narrowed row storage to 32 bits before checking its 256 MiB
allocation limit. For example, a 32-bit image with width 2, height 1 and row
width `0x40000001` could allocate/read four bytes, then upload eight bytes for
its two visible pixels. The source pitch could wrap independently as well.

The loader now validates supported depth and dimensions, bounds the full
64-bit storage size, and only then narrows to the reader's 32-bit byte count.
Encoded payload storage, valid row padding, 24-bit images stored in 32-bit
cells, borrowed palettes and the existing replacement/failure ownership rules
are retained. The texture copier's original odd-width 16-bit behavior is intact.
The bitmap contract supplies the short payload that previously made wrapped
sizes look valid, so these cases do not merely test end-of-file rejection.

## Savedata recursion and invalid inputs

Native Squirrel 2.2 pushes do not grow the VM stack. Each recursive write kept
two iteration values on that stack without reserving room. The serializer also
followed cyclic containers until its byte buffer or native stack was exhausted.
Finally, a failed `BeginIteration` left the operation marked successful, so
saving a scalar could overwrite an existing save with an unreadable empty
serialization.

The writer reserves bounded VM stack space, rejects active-ancestor cycles,
and treats failure to begin iteration as failure. Both read and write accept
up to 256 nested containers including the root, rejecting deeper trees before
unbounded native recursion. The ancestor check allows a shared child to appear
in different branches. Valid wire tags, scalar widths, null omission and tree
serialization remain unchanged. Failed serialization still happens before
opening the destination, preserving the old file.

Regression source covers a fresh small VM, the nesting boundary, independently
encoded excessive nesting, shared children, cycles, invalid root values, stack
balance, old-file preservation and recovery with subsequent valid saves.

## Replay output aliases

The replay status stream was opened with truncation before the recording was
opened. A command such as `--replay source.krec --replay-status source.krec`
therefore destroyed its own input. Parameter parsing now rejects status/input
aliases and active TAS branch/input/status collisions before creating outputs.
Checks cover normalized paths, existing equivalent files (including hard links)
and canonical existing parent directories. Record sessions may still name their
unused `--tas-output` after their recording, preserving the existing launcher
contract. Regression source checks rejected aliases and prior recording bytes.
This does not protect against another process changing links after validation,
or collisions introduced through optional diagnostic environment variables.

## BGM command synchronization

Preparing a BGM track published it to the active queue under one lock, then
scheduling its requested delay took another lock. The update worker could
start the track between those operations while its start time was still zero.
The currently selected handle was also accessed by commands outside the lock
used by worker retirement.

The five public play/play-with-margin/pause/fade/stop commands now hold the
existing recursive audio mutex across their complete operation. Their helper
locks remain valid, and preparation plus scheduling becomes one transaction.
No fade durations, loop flags, gain values or audio backend behavior changed.
The existing audio contract is compiled; no timing stress test or listening
test is claimed for this synchronization change.
